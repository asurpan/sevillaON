# 📘 MANUAL DE OPERACIONES V19.0 - RADIO ON AIR SPAIN (ELITE SUPREME)

Este manual contiene las instrucciones técnicas, comerciales y de seguridad absoluta. Lectura OBLIGATORIA para cualquier IA.

## 🛑 REGLAS DE ORO DEL AGENTE (CRÍTICO)

- **MEMORIA DE SESIÓN**: Al entrar en este proyecto, lee primero `PROTECTED_CORE.md`.

## 🏗️ ARQUITECTURA DE MISIÓN CRÍTICA
1. **RadioAudioManager.kt**: Corazón del AudioContext con motor de supervivencia infrasónico (5Hz) y enrutamiento dinámico Rx/Tx.
2. **RadioMeshModule.kt**: Clase independiente para comunicación P2P en caso de Blackout total.
3. **RadioDialogs.kt**: Gestión de seguridad crítica y disuasión de cambios de Nick.
4. **Screens.kt**: Interfaz Nexus blindada geométricamente.

## ⚠️ REGLAS TÉCNICAS INAMOVIBLES (HARD-LOCK V19.0)

### 🔊 AUDIO, VOZ Y CADENA PTT (BLINDAJE TOTAL)
- **Cadena de Voz Intocable (`voiceBoost` ➔ `txGate` ➔ `txBus`)**: La voz del micro DEBE inyectarse en `txGate` y este a `txBus`. `window.app.voiceBoost` DEBE mantenerse guardado y reconectarse dinámicamente en `initAudio()`.
- **Apertura de Puerta PTT (`txGate`)**: En `broadcastPTT`, la ganancia de `txGate` se abre a **2.5x** al pulsar PTT.
- **AGC Hardware Obligatorio**: `autoGainControl: true` DEBE mantenerse habilitado en `getUserMedia` para que los chips de micrófono de teléfonos Android entreguen ganancia de voz completa (`sensorGain = 4.0`, `voiceBoost = 2.5`).
- **Decoding Bridge**: Mantener siempre la conexión del stream remoto a la salida física con volumen **0.01** vía un nodo Gain `dummy`.
- **Infrasonic Keep-Alive**: Oscilador **5Hz** activo durante silencios de recepción.
- **Re-activación de AudioContext en PTT / Roger Beep**: `broadcastPTT` DEBE ejecutar `window.app.ctx.resume()` si el motor no está en `'running'`.
- **Filtro de Emisión Real para Roger Beep**: El Roger Beep de 1955Hz SOLO suena si el usuario estuvo transmitiendo (`wasTransmitting === true`). Al cambiar de canal se suprime para evitar falsos beeps.

### 📡 RED, PEERJS Y LLAMADA INTELIGENTE
- **Llamada Inteligente Anti-Glare (`mySess < user.id`)**: En el bucle de mantenimiento de `main.kt`, SOLO el cliente con la ID de sesión lexicográficamente menor inicia la llamada saliente.
- **Sanitización Estricta de PeerJS**: La `sessionID` enviada a `new Peer()` DEBE sanitizarse mediante `cleanNick.replace(/[^A-Z0-9_-]/gi, "_")`. Queda prohibido enviar espacios o tildes a PeerJS para evitar el error `invalid-id`.
- **Reconexión por Hardware (`deviceId`)**: En `onUsersUpdate`, se DEBE verificar `otherDeviceId == myDeviceID`. Si la conexión proviene del mismo dispositivo, es reconexión legítima y NO debe expulsar al usuario.
- **ICE Servers Reforzados (4G/5G)**: Es obligatorio el uso de servidores STUN/TURN con transporte TCP (puerto 443).

### 📱 SEGUNDO PLANO Y COMPATIBILIDAD
- **Foreground Service Android 14/15/16**: La app nativa debe ejecutar `RadioService` en primer plano con tipos `mediaPlayback|microphone`.
- **FCM Push High Priority + WakeLock**: `MyFirebaseMessagingService` debe adquirir un `WakeLock` de CPU de 10s y despertar a `RadioService`.
- **Llamadas Nativas (`RadioConnectionService`)**: Integrado con `ConnectionService` y `MANAGE_OWN_CALLS` de Android.
- **Guiado iPhone (iOS Safari)**: La versión Web detecta iPhone y muestra el cartel `ios-install-banner` indicando pulsar *"Añadir a la pantalla de inicio"*.

### 💬 CHAT TÁCTICO
- **Hora de Publicación**: Todos los mensajes muestran la hora `[HH:mm]`.
- **Notificaciones de Privados**: Los mensajes privados y avisos de amigos conectados SIEMPRE emiten sonido. El chat público se puede silenciar con `isChatMuted`.
- **Flujo Multilínea y Auto-Scroll**: Mensajes con `buildAnnotatedString` para salto de línea automático y `animateScrollTo(maxValue)` en el modal.

### 📱 ENTORNO CONMUTABLE ANDROID (LOCAL vs GITHUB SERVIDOR)
- **Variable de conmutación**: En `MainActivity.kt` (línea ~75): `private val USE_GITHUB_REMOTE_SERVER = true` (ó `false`).
- **Cómo conmutar a MODO LOCAL (Desarrollo)**: Si el usuario pide "cambia a local" o "ponlo en local", establecer `USE_GITHUB_REMOTE_SERVER = false` en `MainActivity.kt`.
- **Cómo conmutar a MODO SERVIDOR / GITHUB (Producción)**: Si el usuario pide "cambia a servidor", "ponlo en github" o "modo producción", establecer `USE_GITHUB_REMOTE_SERVER = true` en `MainActivity.kt`.

### 🛑 REGLA SUPREMA DE SEGURIDAD (PERMISO EXPLÍCITO OBLIGATORIO)
- **Flujos Blindados**: El sistema de entrada de usuarios, canales, micrófono, emisión (TX) y recepción (RX) está prohibido de modificar sin permiso explícito por escrito del usuario.
