## ⚠️ REGLAS TÉCNICAS INAMOVIBLES (HARD-LOCK)

### 🔊 AUDIO Y VOZ (BLINDAJE TOTAL)
- **Decoding Bridge**: Mantener siempre la conexión del stream remoto a la salida física con volumen **0.01** (Ajustado para Chrome Mobile) vía un nodo Gain `dummy`. Este puente mantiene la tubería WebRTC "caliente" y evita que Chrome suspenda el proceso de audio.
- **User-Gesture Hack**: El motor de audio DEBE reactivarse (`ctx.resume()`) mediante escuchadores de eventos `click` y `touchstart` globales. Es obligatorio para saltar las restricciones de Autoplay de los navegadores.
- **Infrasonic Keep-Alive**: Mantener siempre el oscilador de **5Hz** activo durante los silencios de recepción. Es el marcapasos inaudible que evita que el navegador o el SO suspendan el hilo de voz. Debe silenciarse (0 absoluto) instantáneamente al detectar voz real.
- **Background Survival (Anti-Sleep)**: Mantener un oscilador ultrasónico de **20.5kHz** con ganancia mínima (**0.001**) conectado permanentemente a la salida física. Esto garantiza que el SO detecte actividad de audio constante y no cierre la pestaña al minimizar el navegador.
- **WakeLock Re-Activo**: El sistema DEBE re-adquirir el `WakeLock` en cada evento `visibilitychange` para asegurar que la pantalla no se duerma tras volver del segundo plano.
- **Replay One-Shot**: El botón debe vaciar la memoria al usarse. Una escucha, una limpieza.
- **Pisado Real (V15.0)**: Usar el motor `WaveShaper` para distorsionar voces débiles. ES CRÍTICO asegurar la inicialización del mapa `remoteDistortion` antes de procesar el motor de prioridades.
- **BLOQUEO DE RUTAS Y VOLUMEN**: Queda TERMINANTEMENTE PROHIBIDO modificar los enrutados de audio (rutas de nodos). Estas rutas están BLINDADAS.
- **Sincronización Discreta**: El PTT DEBE desactivar atómicamente el modo discreto tanto en la UI como en el motor de audio (`window.app.discreteMode = false`) para evitar bloqueos de flujo.

### 📡 VETERANÍA Y RED
- **ICE Servers Reforzados (4G/5G)**: Es obligatorio el uso de servidores STUN/TURN con transporte TCP (puerto 443) para garantizar la comunicación en redes móviles restrictivas (CG-NAT).
- **Progreso de Potencia**: +0.002 pwr / 5s de charla. No regalar veteranía; se gana modulando.
- **Llamada Inteligente**: Solo el ID más bajo llama al más alto. Sagrado para estabilidad en 4G.
- **Persistencia de Nick**: El indicativo del usuario DEBE guardarse en `localStorage` bajo la clave `indicativo` inmediatamente después de la validación. Esto evita que el usuario tenga que re-identificarse en cada sesión web.
- **Indicativo Único (Hard-Lock)**: Queda TERMINANTEMENTE PROHIBIDO permitir duplicados de Nicks activos en diferentes dispositivos. El sistema debe verificar en Firebase si un Nick ya tiene una sesión activa (lastSeen < 45s) con un ID distinto antes de permitir la entrada. Cada indicativo es ÚNICO y está vinculado a su hardware.
- **Advertencia de Olvido**: Si el usuario intenta "olvidar" su indicativo o borrar datos, el sistema DEBE mostrar una advertencia crítica informando de que perderá toda su potencia (Watts) y veteranía acumulada de forma IRRECUPERABLE.
- **Módulo Mesh**: No integrar en la clase principal. Debe permanecer como un recurso de emergencia independiente.
